## 📖 Project Overview & Learning Objectives

โปรเจกต์สื่อการสอนแบบโต้ตอบ (Interactive Web Application) ออกแบบมาเพื่อช่วยให้นักเรียนระดับชั้นมัธยมศึกษาปีที่ 6 เข้าใจทฤษฎีและปรากฏการณ์ของ **คลื่นแม่เหล็กไฟฟ้า (Electromagnetic Waves)** ในหัวข้อ **18.1 การเกิดคลื่นแม่เหล็กไฟฟ้า**, **18.2 สเปกตรัมของคลื่นแม่เหล็กไฟฟ้า**, และ **18.3 โพลาไรเซชันของคลื่นแม่เหล็กไฟฟ้า** ได้แก่ การเหนี่ยวนำข้ามระหว่างสนามไฟฟ้าและสนามแม่เหล็กตามแนวคิดของแมกซ์เวลล์ ($E \perp B \perp v$), อัตราเร็วคลื่นแม่เหล็กไฟฟ้า ($c = f\lambda = 3 \times 10^8 \text{ m/s}$), สเปกตรัมของคลื่นแม่เหล็กไฟฟ้า 7 ช่วงความถี่ (คลื่นวิทยุ, ไมโครเวฟ, อินฟราเรด, แสง, อัลตราไวโอเลต, รังสีเอกซ์, รังสีแกมมา), แสงไม่โพลาไรส์และแสงโพลาไรส์เชิงเส้น ตลอดจนกฎของมาลุส ($I = I_0 \cos^2\theta$) ผ่านการจำลองภาพเสมือนจริง (Virtual Simulation) การฝึกทำโจทย์สุ่มแปรผันตามเลขที่ และระบบสอบเก็บคะแนนแบบจับเวลา

### 🎯 จุดประสงค์การเรียนรู้ (Learning Objectives)

1. **เชิงทฤษฎี**: 
   - อธิบายการเกิดคลื่นแม่เหล็กไฟฟ้าจากการเหนี่ยวนำอย่างต่อเนื่องระหว่างสนามไฟฟ้าและสนามแม่เหล็กตามแนวคิดของแมกซ์เวลล์ และลักษณะเฉพาะของคลื่นแม่เหล็กไฟฟ้า (คลื่นตามขวาง, ไม่อาศัยตัวกลาง, เฟสตรงกัน)
   - อธิบายความหมายของสเปกตรัมคลื่นแม่เหล็กไฟฟ้า สมบัติ คุณลักษณะเด่น และการนำคลื่นแม่เหล็กไฟฟ้าในช่วงความถี่ต่าง ๆ (คลื่นวิทยุ, ไมโครเวฟ, รังสีอินฟราเรด, แสง, รังสีอัลตราไวโอเลต, รังสีเอกซ์, รังสีแกมมา) ไปประยุกต์ใช้ในชีวิตประจำวัน
   - อธิบายปรากฏการณ์โพลาไรเซชัน ความแตกต่างระหว่างแสงไม่โพลาไรส์และแสงโพลาไรส์เชิงเส้น และหลักการทำงานของแผ่นโพลารอยด์
2. **เชิงคำนวณ**: 
   - คำนวณหาอัตราเร็ว ($v$), ความถี่ ($f$), และความยาวคลื่น ($\lambda$) ของคลื่นแม่เหล็กไฟฟ้า โดยใช้สมการ $v = f\lambda$ (หรือ $c = f\lambda$ ในสุญญากาศ)
   - คำนวณความยาวสายอากาศที่เหมาะสมกับการรับ-ส่งคลื่นวิทยุ
   - คำนวณการลดทอนความเข้มแสงและมุมโพลาไรเซชันเมื่อแสงผ่านแผ่นโพลารอยด์ 2 แผ่น ตามกฎของมาลุส ($I = I_0 \cos^2\theta$)
3. **เชิงปฏิบัติการ**: 
   - วิเคราะห์และสังเกตทิศทางของสนามไฟฟ้า ($\vec{E}$), สนามแม่เหล็ก ($\vec{B}$), และทิศทางการเคลื่อนที่ ($\vec{v}$) ตามกฎมือขวา ผ่านเครื่องมือจำลองภาพเสมือนจริง (Virtual Simulator)
   - สำรวจพฤติกรรมและการเปลี่ยนแปลงความเข้มของแสงเมื่อผ่านแผ่นโพลารอยด์ที่ปรับทำมุมต่าง ๆ ($0^\circ - 360^\circ$)

## 🎯 Design Philosophy

แอปพลิเคชันในระบบนิเวศนี้สร้างขึ้นโดยยึดหลักการออกแบบ 7 ประการ เพื่อให้การเรียนรู้วิทยาศาสตร์มีความเที่ยงตรงและยั่งยืน:

* **Learn by Interaction**: การเปลี่ยนผ่านจากความเข้าใจเชิงทฤษฎีไปสู่การมองเห็นภาพจริง เกิดขึ้นได้ดีที่สุดเมื่อผู้เรียนสามารถปรับเปลี่ยนตัวแปรทางฟิสิกส์ (เช่น ความถี่ $\lambda$, ทิศทางสนาม $\vec{E}/\vec{B}$, มุมแผ่นโพลารอยด์ $\theta$) และสังเกตผลลัพธ์ได้ทันทีแบบเรียลไทม์
* **Physics First**: ความถูกต้องแม่นยำของแบบจำลองทางคณิตศาสตร์และสมการฟิสิกส์ ต้องถูกนำมาพิจารณาก่อนความซับซ้อนของกราฟิกหรือเอฟเฟกต์การแสดงผล (Focus on conceptual understanding over visual complexity)
* **Reusable Architecture**: การออกแบบโครงสร้างและมอดูลต้องรองรับการนำรูปแบบไปใช้ซ้ำในบทเรียนอื่นๆ โดยไม่จำเป็นต้องเขียนสถาปัตยกรรมใหม่ทั้งหมด
* **Educational Clarity**: โครงสร้างโค้ดและการออกแบบ UI ต้องสะท้อนความหมายทางฟิสิกส์อย่างตรงไปตรงมา เพื่อให้ทั้งผู้พัฒนาและครูผู้สอนสามารถอ่านและทำความเข้าใจตรรกะได้ง่าย
* **Modular Design**: แยกแยะส่วนประกอบของระบบออกจากกันอย่างเด็ดขาด ป้องกันไม่ให้การเปลี่ยนแปลงจุดใดจุดหนึ่งกระทบกับระบบทั้งหมด
* **Maintainability**: ลดความซับซ้อนที่ไม่จำเป็น เพื่อให้แอปพลิเคชันสามารถดูแลรักษาในระยะยาวได้ง่าย แม้พัฒนาด้วยทีมงานขนาดเล็ก
* **Extensibility**: สามารถเพิ่มฟีเจอร์จำลองใหม่ๆ หรือชุดโจทย์คำนวณเพิ่มเติมได้โดยไม่ต้องรื้อระบบเดิม

## 🏗️ System Architecture

ระบบถูกออกแบบโดยแบ่งลำดับชั้นความรับผิดชอบ (Layered Architecture) เพื่อแยกส่วนประมวลผลทางฟิสิกส์ออกจากส่วนแสดงผลและส่วนปฏิสัมพันธ์กับผู้ใช้:

```text
[ User / Student ]
        │
        ▼
   [ UI Layer ]               (DOM Events, Sliders, Form Controls, Buttons, Angle Knobs)
        │
        ▼
[ Simulator Layer ]           (Topic Orchestrator & State Management)
        │
        ▼
 [ Physics Engine ]           (EM Wave Equations: c = fλ, Malus Law: I = I0 cos²θ Solvers)
        │
        ▼
 [ Domain Models ]            (EM Fields E & B Vectors, Spectrum Bands, Polaroid Model)
        │
        ▼
 [ Renderer Layer ]          (Canvas 2D Rendering Engine & Field Vector Plotter)
        │
        ▼
   [ HTML5 Canvas ]           (Visual Output)
```

### หน้าที่ความรับผิดชอบของแต่ละ Layer:

1. **UI Layer**: รับอินพุตจากผู้ใช้ (เช่น การปรับความถี่ $f$, เลือกช่วงสเปกตรัม, ปรับมุมหมุนแผ่นโพลารอยด์ $\theta$, การกรอกคำตอบ) และส่งต่อ event ไปยัง Simulator
2. **Simulator Layer**: ทำหน้าที่เป็น Orchestrator ควบคุมสถานะของแบบจำลอง (State Management) เชื่อมโยงข้อมูลระหว่าง UI, Engine และ Renderer
3. **Physics Engine**: คำนวณค่าทางฟิสิกส์ล้วนๆ โดยปราศจากส่วนการแสดงผล (Pure Functions) เช่น คำนวณความยาวคลื่น $\lambda = c/f$, ทิศทางเวกเตอร์ $\vec{E} \times \vec{B}$, และความเข้มแสงหลังผ่านโพลารอยด์ $I = I_0 \cos^2\theta$
4. **Domain Models**: จัดเก็บโครงสร้างข้อมูลของวัตถุและคุณสมบัติทางกายภาพ (เช่น ความถี่ช่วงสเปกตรัม, เวกเตอร์สนามไฟฟ้า/แม่เหล็ก, แนวโพลาไรส์ Transmission Axis)
5. **Renderer Layer**: รับค่าสถานะจาก Physics Engine/Models มาวาดเป็นภาพแอนิเมชัน 2D เวกเตอร์คลื่นตามขวาง, สเปกตรัมสี และการส่องผ่านของแสงลงบน HTML5 Canvas
6. **HTML5 Canvas**: พื้นผิวการแสดงผลปลายทางที่แสดงผลลัพธ์เชิงทัศนวิสัยแก่ผู้ใช้

## 🧩 Separation of Concerns

เพื่อความโปร่งใสของโค้ดและการทดสอบที่ง่าย ระบบแยกหน้าที่ความรับผิดชอบ (Separation of Concerns) ตามโดเมนดังนี้:

* **Physics Calculations**: รับผิดชอบเฉพาะสมการทางคณิตศาสตร์ ตัวแปรทางฟิสิกส์ ($v = f\lambda$, $I = I_0 \cos^2\theta$) และการแปลงหน่วย ปราศจากตรรกะของ DOM หรือ Canvas
* **Rendering**: รับผิดชอบเรื่องพิกัดเวกเตอร์ การวาดสนามไฟฟ้า $\vec{E}$ และสนามแม่เหล็ก $\vec{B}$, แถบสเปกตรัมคลื่น, ความสว่างของแสงหลังผ่านแผ่นโพลารอยด์ และการเคลียร์เฟรม Canvas โดยไม่มีตรรกะการคำนวณฟิสิกส์ซ้ำซ้อน
* **User Interface**: รับผิดชอบการผูก Event Listener, การอัปเดตข้อความบนหน้าจอ, แถบควบคุม Slider และการเปลี่ยนสลับแท็บ
* **Quiz Logic**: รับผิดชอบอัลกอริทึมการสุ่มตัวแปร (RNG), การประมวลผลคำตอบตามเลขที่ผู้เรียน ($R$), การตรวจคะแนน และการจัดรูปแบบข้อความเฉลย
* **Learning Content**: จัดเก็บข้อมูลเชิงทฤษฎี ข้อความอธิบาย และการเรนเดอร์สมการ $\LaTeX$ ผ่าน KaTeX
* **Simulation State**: ทำหน้าที่เป็น Single Source of Truth เก็บค่าสถานะปัจจุบันของตัวแปร เช่น ความถี่ ($f$), ความยาวคลื่น ($\lambda$), มุมโพลารอยด์ ($\theta$), ความเข้มแสง ($I$)

## ✨ Features & Interactive Modules

### 1. 📖 ระบบทบทวนบทเรียนและเครื่องมือจำลอง (Interactive Review & Physics Simulators)

* 📡 **Simulator 1 (18.1): การเกิดและลักษณะเฉพาะของคลื่นแม่เหล็กไฟฟ้า**
  * จำลองการเกิดคลื่นแม่เหล็กไฟฟ้าจากการเหนี่ยวนำข้ามระหว่างสนามไฟฟ้า ($\vec{E}$) และสนามแม่เหล็ก ($\vec{B}$) เมื่ออิเล็กตรอนในสายอากาศเคลื่อนที่ด้วยความเร่ง
  * แสดงลักษณะเฉพาะของคลื่นตามขวาง: $\vec{E} \perp \vec{B} \perp \vec{v}$ และหาทิศทางความเร็วการเคลื่อนที่ $\vec{v}$ ด้วยกฎมือขวา
  * แสดงเฟสที่ตรงกันของสนามไฟฟ้าและสนามแม่เหล็ก (เป็นศูนย์และสูงสุดพร้อมกัน) และจำลองการคำนวณ $c = f\lambda = 3 \times 10^8 \text{ m/s}$
* 🌈 **Simulator 2 (18.2): สเปกตรัมของคลื่นแม่เหล็กไฟฟ้า**
  * จำลองแถบสเปกตรัมคลื่นแม่เหล็กไฟฟ้าทั้ง 7 ช่วงความถี่ (คลื่นวิทยุ, ไมโครเวฟ, อินฟราเรด, แสงที่ตามองเห็น, อัลตราไวโอเลต, รังสีเอกซ์, รังสีแกมมา)
  * แสดงความสัมพันธ์ระหว่างความถี่ ($f$), ความยาวคลื่น ($\lambda$), และพลังงานโฟตอน ($E = hf$) แบบ Interactive Spectrum Slider
  * อธิบายการประยุกต์ใช้งานและอันตรายของแต่ละช่วงคลื่น (เช่น การสะท้อนชั้นไอโอโนสเฟียร์ของคลื่นวิทยุ, การทำงานของเตาไมโครเวฟ 2.45 GHz, ครีมกันแดด SPF ป้องกัน UV)
* 🕶️ **Simulator 3 (18.3): โพลาไรเซชันของคลื่นแม่เหล็กไฟฟ้า**
  * จำลองแสงไม่โพลาไรส์ (Unpolarized Light) ที่มีสนามไฟฟ้าสั่นหลายระนาบ และการแปลงเป็นแสงโพลาไรส์เชิงเส้น (Linearly Polarized Light) เมื่อผ่านแผ่นโพลารอยด์
  * จำลองการส่งแสงผ่านแผ่นโพลารอยด์ 2 แผ่น (Polarizer & Analyzer) พร้อมหมุนปรับมุม $\theta$ ($0^\circ - 360^\circ$)
  * แสดงผลระดับความสว่างและความเข้มของแสงที่ทะลุผ่านออกมาตาม **กฎของมาลุส ($I = I_0 \cos^2\theta$)** โดยสว่างมากที่สุดเมื่อ $\theta = 0^\circ, 180^\circ$ และมืดสนิทเมื่อ $\theta = 90^\circ, 270^\circ$

### 2. 🧠 ระบบตะลุยโจทย์เฉพาะตัว (Roll-Number-Based Practice System)

* **โหมดการเรียนรู้**: เลือกได้ระหว่าง *โจทย์ตัวเลขคงที่ (ตามคู่มือ สสวท.)* และ *โจทย์สุ่มตัวเลข (RNG)*
* **หัวข้อคลังข้อสอบย่อย**:
  * `18.1` **การเกิดและลักษณะเฉพาะของคลื่นแม่เหล็กไฟฟ้า**: คำนวณความถี่ ความยาวคลื่น ($c = f\lambda$), ทิศทางสนามตามกฎมือขวา, คุณสมบัติคลื่นตามขวาง และสายอากาศ
  * `18.2` **สเปกตรัมของคลื่นแม่เหล็กไฟฟ้าและการประยุกต์**: เปรียบเทียบความถี่/พลังงานช่วงสเปกตรัม, คำนวณความยาวสายอากาศ ($L = \lambda/2$ หรือ $\lambda/4$), การประยุกต์ใช้ประโยชน์ (AM/FM, เตาไมโครเวฟ, กล้องอินฟราเรด, รังสีเอกซ์)
  * `18.3` **โพลาไรเซชันของคลื่นแม่เหล็กไฟฟ้า**: คำนวณความเข้มแสงหลังผ่านแผ่นโพลารอยด์ 1 แผ่น และ 2 แผ่น ($I = I_0 \cos^2\theta$), ทิศทางแนวโพลาไรส์
* **ระบบเฉลยละเอียด**: แสดงผลการตรวจคำตอบทันทีพร้อมวิธีทำคำนวณสูตรฟิสิกส์ทีละขั้นตอนอย่างละเอียดในรูปแบบสัญลักษณ์คณิตศาสตร์ $\LaTeX$ ผ่าน KaTeX

## ⚙️ Dynamic Quiz System Rules

ระบบข้อสอบถูกออกแบบให้เป็น **Non-Deterministic Dynamic System** โดยผูกค่าตัวแปรในโจทย์เข้ากับ **"เลขที่ของนักเรียน (Roll Number: $R$)"** เพื่อให้มั่นใจว่านักเรียนแต่ละคนจะได้รับพารามิเตอร์โจทย์และคำตอบที่ไม่ซ้ำกัน

### 📌 สถาปัตยกรรมและลอจิกการทำงาน:
1. **Dynamic Parameter Generation**: ระบบจะดึงเลขที่ของนักเรียน ($R \in [1, 40]$) มาคำนวณร่วมกับฐานตัวแปรที่ถูกสุ่มขึ้นมาแบบอิสระ (*Non-deterministic Random*) เพื่อสร้างค่าพารามิเตอร์ชุดใหม่สำหรับโจทย์แต่ละข้อ
2. **On-the-fly Validation**: การประเมินคำตอบและเฉลยวิธีทำจะคำนวณแบบสดๆ (*On-the-fly*) จากเลขที่ $R$ ของผู้เข้าสอบจริง โดยไม่ใช้ค่าคงที่แบบสแตติก (*No Static Hardcoded Answers*)
3. **Safety Constraints**: สมการเบื้องหลังได้รับการกำหนดขอบเขตค่าต่ำสุด-สูงสุดไว้อย่างรัดกุม ป้องกันไม่ให้การคำนวณร่วมกับเลขที่ $R$ เกิดค่าที่ติดลบหรือผิดหลักการทางฟิสิกส์

## 🛠️ Development Principles

ผู้พัฒนาที่ต้องการสร้าง Simulator หรือ Repository ใหม่ในระบบนิเวศนี้ ควรปฏิบัติตามหลักการต่อไปนี้อย่างเคร่งครัด:

1. **Keep Physics Independent from Rendering**: ห้ามเขียนสูตรคำนวณทางฟิสิกส์ปะปนในฟังก์ชันวาด Canvas หรือ Event Listener
2. **Avoid Duplicated Formulas**: ศูนย์รวมสูตรและสมการฟิสิกส์ต้องถูกจัดการผ่าน Physics Engine หรือ Helper Module เพียงจุดเดียว
3. **Separate UI from Simulation Logic**: ส่วนติดต่อผู้ใช้ต้องมีหน้าที่เพียงส่งผ่าน Parameter และแสดงผลลัพธ์ ไม่ตัดสินตรรกะการจำลอง
4. **Keep Reusable Modules**: ออกแบบโค้ดในลักษณะโมดูลที่สามารถคัดลอกหรือ Import ไปใช้ในหัวข้อฟิสิกส์อื่นได้สะดวก
5. **Be Easy to Test**: ฟังก์ชันประมวลผลฟิสิกส์ต้องรับอินพุตและคืนค่าเอาต์พุตอย่างตรงไปตรงมา (Pure Functions) เพื่อรองรับ Unit Testing
6. **Be Easy to Extend**: เพิ่มช่วงคลื่นสเปกตรัมใหม่ พารามิเตอร์มุมโพลาไรเซชัน หรืออุปกรณ์ประยุกต์ใหม่ได้โดยการปรับแก้เพียงไฟล์ Model/Config

## 🌐 Repository Strategy & Educational Ecosystem Roadmap

### 1. ยุทธศาสตร์แยก Repository (Modular Repository Strategy)
โปรเจกต์นี้ **ไม่ใช่แอปพลิเคชันแบบ Monolithic** ที่รวมฟิสิกส์ทุกบทไว้ในซอร์สโค้ดเดียว แต่ละหัวข้อการเรียนรู้ (รวมถึง Unit 18.1 - 18.3 และบทต่อๆ ไป) จะมี **Repository แยกเป็นเอกเทศของตนเอง** 

* **แชร์ปรัชญา แต่ไม่แชร์โค้ดที่ซับซ้อนเกินจำเป็น**: แต่ละ Repository จะยึดถือปรัชญาการออกแบบ (Design Philosophy) และสถาปัตยกรรม (Architecture Blueprint) เดียวกัน
* **รองรับความหลากหลายทางฟิสิกส์**: หัวข้อฟิสิกส์ที่ต่างกัน เช่น *Electromagnetic Waves (คลื่นแม่เหล็กไฟฟ้า), Fluid Dynamics (พลศาสตร์ของไหล), Projectile Motion (การเคลื่อนที่แบบโปรเจกไทล์), Electricity (ไฟฟ้า)* และ *Atomic Physics (ฟิสิกส์อะตอม)* อาจใช้ Engine ภายในที่ต่างกันโดยสิ้นเชิง แต่ยังคงโครงสร้างสถาปัตยกรรมและการแยกชั้น Layer เดียวกัน

```text

   ▼                             ▼                             ▼
[ Unit 18 Repository ]     [ Unit 17 Repository ]    [ Future Topic Repositories ]
 (EM Waves: 18.1-18.3)      (Fluid Dynamics)          (Atomic Physics, Nuclear, etc.)
   │                             │                             │
   └─────────────────────────────┴─────────────────────────────┘
```

* **Cross-Topic Ecosystem Consistency**: เพิ่มความสอดคล้องของ UI/UX และระบบเซฟคะแนน LocalStorage ให้รองรับการทำงานข้ามหัวข้อการเรียนรู้
* **Topic Expansion**: ขยายการสร้าง Repository ไปยังบทเรียนอื่นๆ ในระดับชั้นมัธยมศึกษาอย่างเป็นระบบ
